# Hallmark

## Authenticity

- Ground copy, examples, and interface details in the real product and its actual capabilities.
- Never invent customer quotes, usage counts, ratings, performance claims, or other metrics. Label placeholders clearly when a mockup requires them.
- Avoid stock-like decoration, generic AI-style layouts, and visual details that do not support the subject or workflow.
- Use assets that show the actual product, place, object, or state when users need to inspect it.

## Design system

- Define and reuse a small, coherent set of color, type, spacing, and surface tokens.
- Let typography and composition express the product's character without harming readability or accessibility.
- Keep component styling consistent across states and screen sizes. Do not add a competing design language to an established system.

## Review

- Check that visible claims are supported by repository data or explicitly supplied content.
- Check responsive behavior, contrast, focus, and content fit.
- Prefer specific, credible details over decorative complexity.
